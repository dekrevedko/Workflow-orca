# Wait ownership: requirements, model, and implementation

Historical pilot baseline. See the [current implementation and results](README.md#current-implementation).

Source baseline: `323d741d4c33178430250729b4fa34f1eeb61703` (proposal commit; production source inherited from `ba2b057d7898f516845e90323b4288fb0c1744d8`). Exact run inputs are hashed by the runner in `source-manifest.json`; a revision alone does not cover new uncommitted model/test files.

## Scope and observable boundaries

The model has two instances and two occurrence slots per instance. Slots represent sibling registration attempts or successive occurrences. Both occurrences of an instance use the same full key. Four isolation profiles change exactly one of definition, contract name, contract version, or correlation between instances. Events have two opaque identities with at most two submissions per identity per target. There is at most one escaping failure per occurrence; counters never wrap. No symmetry or state-space constraint discards a violating prefix.

All modeled waits can acquire a queued timer callback carrying their occurrence identity. Stale callbacks may dispatch after the original wait resolves; WOP-007 compares captured before/after successor state, reservations, index, and resolution counts. A due timer is a nondeterministic action, not wall-clock simulation. Instance cancellation/terminal failure is a request followed by lane-serialized cleanup; caller cancellation is represented by an escaping continuation, with no instance terminal request. Successful consumption and continuation attempts are separate. Matched old/new-active reservations may coexist within one owner. All safety predicates are checked at each modeled state, including the exposed cross-instance reservation boundaries.

`Register` combines the same-instance list update with its atomic index reservation. The real `routingGate` is released before the active-list insertion, but the instance lane prevents a same-instance contender during that interval; another instance can already observe reservation ownership. The abstraction publishes the new wait immediately, an over-approximation of route visibility. `Lookup`, `Observe`, `Enqueue`, `Deliver`, `Successor`, `Return`, `Escape`, `Settle`, and `Release` remain separate. `Busy(i)` represents the lane held across await; another instance remains free. Snapshot visibility is a boolean per key, not a copy of the full fiber state. The index may change between lookup and observation. This is an abstraction, not a mechanized refinement proof.

The modeled ingress is correlation selection for a fixed target and key, with exact envelope identity. It does not model changed-envelope fingerprint conflicts, arbitrary fanout, or direct pre-wait injection. Lower-level `WorkflowInstance.RaiseEventAsync` can buffer unmatched events; the correlation/facade path rejects unmatched published waits before enqueue. In this same-key two-occurrence fragment a stale queued request is deduplicated, consumed by the next active occurrence, or ignored after prior consumption/timeout. An independent direct pre-wait mailbox is not modeled. Existing `DeliveryRecoveryTests` cover that lower-level buffer path separately; they do not grant model credit for it.

`WorkflowInstance` retains 10,000 consumed IDs by default. The modeled two identities never reach that bound. The router's acceptance bookkeeping and retention cleanup are distinct from this history. No post-eviction deduplication, durable acknowledgement, crash survival, or production payload guarantee follows.

The executable integration scenarios use public workflow authoring and the existing `OrcaCore.TestSupport.ProcessLocalEventRouter` bridge into production routing. That adapter explicitly keeps process-local scenarios off the removed public event-client surface. These tests exercise actual production internals through established friend access; they do **not** establish a currently shipped public ephemeral ingress API.

## Confirmed source discrepancy: WOP-F001

The successor-then-escaping-failure state is reachable on the actual structured authoring/runtime route. A deterministic test suspends the second correlation selector, cancels the route caller's token from a separate thread, then releases the selector. The selector still returns the same deterministic key; cancellation is external, not a side effect encoded into the correlation value.

1. `EphemeralWorkflowEngine.RaiseEventCoreAsync` queues a linked caller token on the instance lane.
2. `WorkflowInstance.ResumeWaitAsync` removes the predecessor but keeps its reservation.
3. `InMemoryExecutionStateAdapter.ResumeFiberAsync` resumes the fiber and invokes `RunUntilBoundaryAsync`.
4. The loop checks cancellation, then invokes the successor's selector. `RegisterFiberWaitAsync` registers the successor and advances the fiber without another token check.
5. The next loop iteration observes cancellation and throws.
6. `ResumeWaitAsync` catch restores the predecessor without removing the successor or restoring the structured execution position.

The actual state has two active same-key occurrences and two same-instance reservations. The immediate published snapshot can hide the restored predecessor because rollback does not publish it. The regression executes the authoring/runtime path then uses existing friend access to inspect actual state. It fails the contract assertion instead of asserting that the defect is desirable.

The normal model keeps this escape enabled (`RollbackMode = "source"`) and fails WOP-002. Fault qualification profiles use `before-successor` only to isolate seeded faults from this already known defect; that is a deliberately restricted diagnostic control, **not** a repaired protocol or a passing production baseline. The normal safety/progress profiles never use that restriction.

The separate source-mapping reviewer confirmed the source chain before the experiment. The deterministic C# regression and TLC trace both confirmed it afterwards. Root wait timeout normally fails the workflow; the generic timer rollback model is additionally supported by the lower-level `DeliveryRecoveryTests`, not a claimed arbitrary public root timeout continuation. Any remaining scheduler-specific timer effects are outside this small fragment.

## Progress and control qualification

Normal `ProgressSmall` checks the same source protocol as safety, adding weak fairness of continuously enabled internal settlement/release/registration and eventual continuation return. Finite arrivals and one failure per occurrence are explicit bounds, not a guarantee of external event arrival. No workflow-termination or claimant-fairness promise is made.

The two assumption-removal controls have an explicit separate initial condition with one already admitted continuation. They keep the same finite domains but no new arrivals and apply fairness only to actions in their own transition relation; their purpose is to show that withholding return or internal scheduling permits non-progress. They are not normal-model coverage. The companion `Control-Progress` restores both assumptions and must pass, while `Witness-ControlComplete` reaches successful release, checking that the fairness assumptions admit completed behavior. Their sole temporal property is `ConditionalSettlement`, allowing the runner to identify the failed obligation even though TLC 1.7.4 prints a generic temporal-property failure message. Normal `ProgressSmall` fails safety before granting liveness credit while WOP-F001 remains unresolved.

Mutation profiles check their named property plus `TypeOK`, isolating early release, missing same-instance guard, successor deletion, consumed-on-failure, dual winner, and stale callback retargeting. The latter must violate WOP-007; its trace qualifies the callback isolation check. Race witnesses require a completed winner and losing-path handling, and cancellation witnesses require prior live ownership followed by cleanup. Witness profiles deliberately violate `NotWitness` and retain the path; they are reported as expected counterexamples, never normal-model passes. A checker parse error, unrelated invariant, or timeout is rejected by the runner self-tests.
