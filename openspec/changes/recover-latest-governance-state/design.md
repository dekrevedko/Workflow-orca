## Context

A governance command already writes a complete v1 state comprising pools, tickets, queued waiters, expired tickets, resize operations, release evidence and confirmation bindings. Replaying earlier full states repeatedly validates and discards their decoded values. The last state contains all facts needed to make the next decision and preserve deduplication.

## Decisions

**Port and consistency.** Add `LoadLatestAsync(partitionId, cancellationToken)` beside the existing explicit history read. `ResourceGovernanceHead.Create(partitionId, version, record)` validates the metadata shape. Always return the requested partition, including for an uninitialized partition (version zero, null record). For an existing positive head, return one detached record with the same sequence. Storage selection, not a new field in the v1 envelope, binds the record to its partition. The engine also compares returned and requested partition IDs before using the state.

**Read and mutation path.** Read one head for each attempt. Validate record format and checksum and deserialize its full state. Verify the supported envelope kind and current accounting invariants before reading pool state or choosing an append. A missing or invalid current record fails closed. Append at the observed version. If a concurrent writer wins, reload its new head before recomputing. This preserves multi-pool atomicity, capacity reservations, queued order, resize debt, binding identity and tombstones. Explicit `LoadAsync` continues to validate full record history. Its sequence and checksum checks remain independent of decoding aggregate business state.

**Providers.** PostgreSQL uses one statement snapshot containing the authoritative partition head and the highest-sequence record for that partition. The existing primary keys support both probes. A record ahead of the head or a head with no matching latest row fails. The in-memory store takes its lock, uses the committed version and selects one record. Valid detached records remain isolated from caller mutation. Experimental SQL Server reads its transactionally stored state document. It can traverse or transfer history bytes to locate the selected partition's record. Validate the selected record for the hot read. New SQL Server writes include a per-partition version in the existing JSON document so removal of the newest record can be detected. Only absence of the version field in a legacy partition permits its record count to supply the version. The selected sequence must agree. A present null, non-integral, negative or mismatched version fails. A coherent suffix removal without an independent version can look identical to a shorter legacy history. Reading a legacy document never saves or migrates it. Replacing a whole document with an older internally consistent one cannot be detected without an external authority. Whole-document restores and writes may still depend on historical length. Existing valid v1 state stays readable without a database migration.

**Alternatives.** Replacing `LoadAsync` would discard an existing full-history and provider-certification surface. A default interface method that builds the head from a full load would preserve the original read amplification and could hide a missing committed head. An identity ledger, compaction or a native SQL Server storage rewrite would address different costs.

## Evidence and limits

Compare current-state recovery against valid history using ordered waiters, active and quarantined tickets, releases, resize/confirmation replays and existing crash barriers. Exercise positive head with no record, wrong partition or sequence, malformed current state, bad checksum and a concurrent winning append. Show separately what explicit full-history validation detects. Use real PostgreSQL and experimental SQL Server for provider behavior.

Measure fixed current state while history grows and separately grow retained current state. Record logical records and bytes returned, aggregate states decoded, provider storage work, allocation and latency. PostgreSQL must demonstrate the indexed lookup independent of the number of prior payloads. Current state size, the cost of checking ownership and the cost of writing a full record can still grow. SQL Server physical document and write costs remain open before promotion.
