## Why

OrcaCore is preparing its first release with no compatibility obligations, but its provisional public surface mixes application authoring, durable protocol, provider, and implementation concepts and exposes several features whose complete semantics are not yet approved. This change establishes a smaller, coherent v1 contract centered on typed workflows, structured concurrency, durable resource safety, and a separately packaged DAG compiler before those provisional shapes become promises.

## What Changes

- **BREAKING** Replace the mixed/provisional workflow API with mode-first typed definitions and reusable typed workflow references. Workflow input and output types are explicit, each mode has exactly four non-nullable resultless/resultful `End` overloads, `End` commits the output atomically, and optional fixed `WorkflowOutcomeName` metadata remains distinct from domain output.
- **BREAKING** Standardize every caller-created string-backed strong value on a private constructor plus `Create(string)`. Do not retain public constructors, `New`, `Parse`/`TryParse`, implicit conversions, raw-string overloads, or aliases for that family; runtime-created identities keep canonical parsers and generated definition identity keeps `New`.
- **BREAKING** Publish only the complete v1 node set: business steps, `Init`, `End`, `Delay`, event `Wait`, root `While`, nested `If`, root-only fixed `Parallel`, bounded root-only `ForEach`, `WhenAll`, `WhenAllOutcomes`, terminal durable-root `ContinueAsNew`, and scoped durable `AcquireResources`.
- **BREAKING** Remove `WaitLong` and `Yield`. Wait residency is a runtime/hosting policy rather than an authored node distinction; cooperative turn scheduling is internal.
- **BREAKING** Defer public `RunExternalJob`, saga authoring/execution, `WhenFirst`, public `RunChild`/`RunChildren`, nested `Parallel`/`While`/`ForEach`, durable lambdas, definition-wide retry, failed-instance/step management retry, public pause/resume/archive/purge, workflow-authored `Publish`/`Cancel`, and definition-targeted event fanout. Record each deferred item in an explicit future-capability registry, with no alias, obsolete tombstone, placeholder member, or callable provisional contract in v1.
- Add non-empty root-only `Parallel(...).WhenAll(...)` and `Parallel(...).WhenAllOutcomes(...)`; an empty scope is a `Build`/`TryBuild` graph diagnostic, and no nested, branch, item, or leased builder exposes `Parallel`. `WhenAll` merges only successful branch results and otherwise produces one ordered failure or `SFE-JOIN-FAILED` aggregate. `WhenAllOutcomes` supplies ordered success/failure outcomes only; ancestor cancellation, termination, or workflow deadline suppresses either merge rather than becoming a merge-visible cancellation value. Merge is the only place where parent state changes from branch results.
- Add bounded `ForEach` to both modes. Durable `ForEach` commits one finite deterministic fixed-codec item snapshot, enforces an explicit positive upper bound, persists item identity/progress, accepts an empty snapshot and invokes the selected merge once with an empty ordered list, and joins through the same all-results semantics. Both modes may tighten host path admission with node-local `MaxConcurrency`; only ephemeral item bodies may use lambda steps.
- Allow lambda step bodies only in ephemeral authoring. Durable definitions use registered typed steps so restart behavior, version binding, dependency construction, and fingerprints remain explicit.
- Fix v1 serialization to the certified `System.Text.Json` codec format `orcacore-json-v1`. Selectors, copies, persisted inputs/state/results, idempotency fingerprints, and query projections use codec-detached values; unsupported/cyclic/unapproved polymorphic shapes fail before commit.
- Give every business-step attempt a codec-detached attempt-local state copy and `StepContext<TState>.ReplaceState(...)`. Only the winning successful attempt commits; failed/timed-out copies are discarded, and a token-ignoring late body may physically overlap a retry while retaining no logical commit authority.
- Add exact retry, workflow deadline, structural wait timeout, and business-step timeout semantics. Retry covers authored failure, normalized exception, and attempt timeout only; `CompleteWithin(...)` persists one start-relative deadline across every continue-as-new generation; `WithStepTimeout(...)` fences one attempt. Polly does not own orchestration state, and an ambiguous external side effect is never assumed absent merely because a timeout elapsed.
- Add runtime-created `StepOperationId` to step execution context. It identifies one logical step occurrence, remains stable across retry/replay/host replacement, changes for a new loop/item/branch occurrence, and is suitable for create-or-observe idempotency. Attempt number is a durable retry-policy ordinal: crash redispatch reuses it, and only a committed retry transition increments it.
- Replace point/fiber-lifetime resource acquisition with scoped-only `AcquireResources(nonEmptyRequest, body)`. `ResourceLeaseRequest` and `ResourceLeaseRequirement` are immutable factory-created values; there is no author TTL, renewal, holder ID, or acquisition-timeout overload. Compiler and runtime enforce the inclusive live-ancestor rule, and dedicated leased builders expose no fan-out, nested acquisition, or `ContinueAsNew`. Retryable ambiguity retains the same capacity-reserving lexical obligation; scope abandonment transfers it to quarantine before parent progress, and only trusted stop/fence proof makes release safe.
- Introduce complete resultless/resultful DAG planning and operation contracts in `OrcaCore.Dag`, plus `OrcaCore.Dag.Hosting` as the sole runtime bridge. Each DAG node references a typed durable workflow, executes as one deterministic child instance, maps input from immutable run input plus direct successful dependency outputs, and exposes stable authored-order status/snapshot/output/start results. The bridge uses a named versioned internal child-start/join contract exposed by `OrcaCore.Durable.Hosting` only through `InternalsVisibleTo("OrcaCore.Dag.Hosting")`; public `RunChildren` remains absent.
- Keep OrcaCore independent of Kubernetes, AWS, and job-scheduler libraries. A companion scheduler/integration project may live in the same solution and depend outward on OrcaCore. It uses `StepOperationId`, ordinary typed steps, durable waits, and trusted lease stop/fence confirmation; OrcaCore never references it.
- Bind a durable instance to immutable `(DefinitionId, DefinitionVersion, structural fingerprint)`. The fingerprint covers inspectable authored structure and codec format only. Changing selector/projector/merge/output code, step construction/configuration, DAG mapping, or external-request construction requires a new definition version; v1 has no author-supplied fingerprint contributor.
- Separate application, engine/hosting, provider-authoring, runtime-protocol, and implementation tiers. Hide compiled IR, fiber/scope routing identities, commands, checkpoints, provider records, and hosted-loop implementations from normal application contracts.
- Publish the exact ordinary application facade: explicit typed definition registration; a closed registered/host-incompatible/fingerprint-conflict result with deterministic mode/static-pool/fingerprint validation and cast-free `GetHandleOrThrow()` projection; closed typed start results; typed start/reopen handles; detached snapshot/root-state/output queries; notification-driven output and DAG-terminal waits; cooperative cancellation request; immediate fenced termination; and instance/correlation event delivery. Pause/resume/retry/archive/purge, instance enumeration/bulk selection/query/statistics, and definition-targeted fanout are deferred. Correlation routing rejects ambiguous active wait pairs at registration and uses non-buffering signal-stream semantics.
- Publish only role-specific hosting: `AddOrcaCoreEphemeralEngine`, `AddOrcaCoreDurableEngine`, callback-only `AddOrcaCoreDurableEventIngress`, development/test `AddOrcaCoreInMemoryDurableProvider`, production `AddOrcaCorePostgreSqlDurableProvider`, and `OrcaCore.Dag.Hosting.AddOrcaCoreDag`, with split extension owners and programmatic options, mutually exclusive engine roles, and no catch-all `AddOrcaCore`, separate hosted-service toggle, implicit mode, serializer hook, or binder claim.
- Make `OrcaCore` the primary application contracts/authoring package rather than a dependency-only meta-package. Fix every v1 PackageId/assembly owner/direct edge and validate clean consumers from the repository-local Phase 0 feed.
- Define durable resource governance as one serialized aggregate per configured provider partition, with fixed FIFO request order, atomic multi-pool grants, typed unknown-pool rejection before mutation, positive-only resize, exact grant/cancel and confirmation precedence, immutable creation definitions distinct from replayed current capacity, exact reservation/resize/confirmation accounting, and one expected-version `IDurableResourceGovernanceStore` append contract.
- Define the per-instance execution-path token model: runnable root/branch/item fibers own one token; parking and joins release it; parents release before root fan-out and reacquire for merge; root fixed branches and root-`ForEach` items queue deterministically; timed-out token-ignoring bodies retain only physical throttle/transient capacity.
- Make `docs/specs/17-public-authoring-contract.cs` together with the selected-mode matrix the exact compile/reflection guard baseline. Add the complete diagnostic/location catalog, codec, detached-attempt-state, public-facade/event, reactive-wait, path-token, runtime-pre-child DAG mapping, resource-governance provider, deterministic four-barrier crash, restart, deadline, structured-join, operation-identity, and lease-protocol guards. Every Phase 0 task 3.1 through 3.12 and an independent approval are required before implementation proceeds.

## Capabilities

### New Capabilities

- `developer-facing-surface`: Defines the v1 application surface, tier/package boundaries, explicit future-capability registry, and supported consumer journeys.

### Modified Capabilities

- `workflow-authoring`: Defines mode-first typed workflows, the reduced node matrix, joins, bounded durable `ForEach`, ephemeral lambdas, deadlines, scoped leasing, and deferred-node absence.
- `workflow-contracts`: Defines typed workflow references/input/output, branch and item outcome contracts, `StepOperationId`, immutable lease requests, and portable step boundaries.
- `durable-runtime`: Defines durable deadlines, stable step occurrence identity, wait residency, scoped lease ownership/reconciliation, immutable definition binding, and runtime-owned DAG progression.
- `management-and-querying`: Aligns typed asynchronous handles and exposes safe durable lease quarantine/reconciliation operations.
- `saga-orchestration`: Removes saga from the v1 callable surface while retaining an explicit future capability entry.
- `repository-foundation`: Establishes one-way package direction, `OrcaCore.Dag`, and strict separation from Kubernetes/AWS/job-scheduler projects.
- `quality-and-verification`: Replaces rejected guards and adds mechanical proof for the final v1 surface and its deferred absences.

## Impact

- Affected product areas include application contracts and authoring, both engines, the durable driver, hosting, management, providers, `OrcaCore.Dag`, samples, tests, package metadata, and canonical specifications.
- Existing names and signatures are provisional. Implementation SHALL delete rejected paths directly and SHALL NOT add compatibility shims, obsolete aliases, or placeholder members.
- The archived structured-fiber implementation remains the execution substrate, but its provisional authoring surface is not accepted merely because source already exists.
- `add-runtime-concurrency-limits` remains coordinated for transient host limits. The host owns `MaxConcurrentExecutionPathsPerInstance`; root fixed-`Parallel` branches are admitted in authored order, both-mode root `ForEach` uses the lower of host and node-local limits, and DAG scheduling uses its separate node limit.
- Kubernetes/EKS/AWS scheduling remains a companion integration concern. OrcaCore supplies only generic workflow, identity, wait, deadline, and resource-safety contracts.
