## Why

OrcaCore is preparing its first release with no compatibility obligations, but its provisional public surface mixes application authoring, durable protocol, provider, and implementation concepts and exposes several features whose complete semantics are not yet approved. This change establishes a smaller, coherent v1 contract centered on typed workflows, structured concurrency, durable resource safety, and a separately packaged DAG compiler before those provisional shapes become promises.

## What Changes

- **BREAKING** Replace the mixed/provisional workflow API with mode-first typed definitions and reusable typed workflow references in both modes. Workflow input and output types are explicit, each mode has exactly four non-nullable resultless/resultful `End` overloads, `End` commits the output atomically, and optional fixed `WorkflowOutcomeName` metadata remains distinct from domain output.
- **BREAKING** Standardize every caller-created string-backed strong value on a private constructor plus `Create(string)`. Do not retain public constructors, `New`, `Parse`/`TryParse`, implicit conversions, raw-string overloads, or aliases for that family; runtime-created identities keep canonical parsers and generated definition identity keeps `New`.
- **BREAKING** Publish only the complete v1 node set: business steps, `Init`, `End`, `Delay`, event `Wait`, root `While`, nested `If`, root-only fixed `Parallel`, bounded root-only `ForEach`, `WhenAll`, `WhenAllOutcomes`, terminal durable-root `ContinueAsNew`, and scoped durable `AcquireResources`.
- **BREAKING** Remove `WaitLong` and `Yield`. Wait residency is a runtime/hosting policy rather than an authored node distinction; cooperative turn scheduling is internal.
- **BREAKING** Defer public `RunExternalJob`, saga authoring/execution, `WhenFirst`, public `RunChild`/`RunChildren`, nested `Parallel`/`While`/`ForEach`, durable lambdas, definition-wide retry, failed-instance/step management retry, public pause/resume/archive/purge, and workflow-authored `Cancel`. Record each deferred item in an explicit future-capability registry, with no alias, obsolete tombstone, placeholder member, or callable provisional contract in v1. Durable workflow-authored `Publish` and explicit definition-scoped fanout are included only through the durable inbox/outbox contract defined by this change.
- Add non-empty root-only `Parallel(...).WhenAll(...)` and `Parallel(...).WhenAllOutcomes(...)`; an empty scope is a `Build`/`TryBuild` graph diagnostic, and no nested, branch, item, or leased builder exposes `Parallel`. `WhenAll` merges only successful branch results and otherwise produces one ordered failure or `SFE-JOIN-FAILED` aggregate. `WhenAllOutcomes` supplies ordered success/failure outcomes only; ancestor cancellation, termination, or workflow deadline suppresses either merge rather than becoming a merge-visible cancellation value. Merge is the only place where parent state changes from branch results.
- Confirm root-only fan-out as the v1 boundary. Root fan-out stages compose sequentially because every join returns the root builder and replaces parent state. Tagged-item flattening and sequential staging cover common nested journeys only when authored item limits, fixed encoded-value budgets, dependency ordering, failure attribution, per-group concurrency, and barrier placement remain acceptable. Nested `Parallel` is therefore declined for v1; the remaining unbounded data-dependent repetition needs nested `ForEach` or a separately specified continuation mechanism, not nested fixed fan-out.
- Add bounded `ForEach` to both modes. Durable `ForEach` commits one finite deterministic fixed-codec item snapshot, enforces an explicit positive upper bound, persists item identity/progress, accepts an empty snapshot and invokes the selected merge once with an empty ordered list, and joins through the same all-results semantics. Both modes may tighten host path admission with node-local `MaxConcurrency`; only ephemeral item bodies may use lambda steps.
- Govern every mutable builder façade through one phase- and scope-bound authoring session. Root terminal selection atomically freezes the authored graph, completion builders build only that snapshot, stale/superseded/escaped handles and duplicate join selection are rejected without graph mutation, and repeated `Build`/`TryBuild` calls are structurally stable.
- Allow lambda step bodies only in ephemeral authoring. Durable definitions use registered typed steps so restart behavior, version binding, dependency construction, and fingerprints remain explicit.
- Fix v1 serialization to the certified `System.Text.Json` codec format `orcacore-json-v1`. Selectors, copies, persisted inputs/state/results, idempotency fingerprints, and query projections use codec-detached values; unsupported/cyclic/unapproved polymorphic shapes fail before commit.
- Give every business-step attempt a codec-detached attempt-local state copy and `StepContext<TState>.ReplaceState(...)`. Only the winning successful attempt commits; failed/timed-out copies are discarded, and a token-ignoring late body may physically overlap a retry while retaining no logical commit authority.
- Add exact retry, workflow deadline, structural wait timeout, and business-step timeout semantics. Retry covers authored failure, normalized exception, and attempt timeout only; `CompleteWithin(...)` persists one start-relative deadline across every continue-as-new generation; `WithStepTimeout(...)` fences one attempt. Polly does not own orchestration state, and an ambiguous external side effect is never assumed absent merely because a timeout elapsed.
- Add runtime-created `StepOperationId` to step execution context. It identifies one logical step occurrence, remains stable across retry/replay/host replacement, changes for a new loop/item/branch occurrence, and is suitable for create-or-observe idempotency. Attempt number is a durable retry-policy ordinal: crash redispatch reuses it, and only a committed retry transition increments it.
- Replace point/fiber-lifetime resource acquisition with scoped-only `AcquireResources(nonEmptyRequest, body)`. `ResourceLeaseRequest` and `ResourceLeaseRequirement` are immutable factory-created values; there is no author TTL, renewal, holder ID, or acquisition-timeout overload. Compiler and runtime enforce the inclusive live-ancestor rule, and dedicated leased builders expose no fan-out, nested acquisition, or `ContinueAsNew`. Retryable ambiguity retains the same capacity-reserving lexical obligation; scope abandonment transfers it to quarantine before parent progress, and only trusted stop/fence proof makes release safe.
- Introduce complete resultless/resultful DAG planning and operation contracts in `OrcaCore.Dag`, plus `OrcaCore.Dag.Hosting` as the sole runtime bridge. Each DAG node references a typed durable workflow, executes as one deterministic child instance, maps input from immutable run input plus direct successful dependency outputs, and exposes stable authored-order status/snapshot/output/start results. The bridge uses a named versioned internal child-start/join contract exposed by `OrcaCore.Durable.Hosting` only through `InternalsVisibleTo("OrcaCore.Dag.Hosting")`; public `RunChildren` remains absent.
- Keep OrcaCore independent of Kubernetes, AWS, and job-scheduler libraries. A companion scheduler/integration project may live in the same solution and depend outward on OrcaCore. It uses `StepOperationId`, ordinary typed steps, durable waits, and trusted lease stop/fence confirmation; OrcaCore never references it.
- Bind a durable instance to immutable `(DefinitionId, DefinitionVersion, structural fingerprint)`. The fingerprint covers inspectable authored structure and codec format only. Changing selector/projector/merge/output code, step construction/configuration, DAG mapping, or external-request construction requires a new definition version; v1 has no author-supplied fingerprint contributor.
- Repair fingerprint conformance by excluding compiler format, workflow mode, definition identity/version, and every compiler option from the structural fingerprint. Compiler format remains a separate resume binding, and a durable host retains every format referenced by a nonterminal instance unless an explicit migration or pre-v1 hard cutover applies.
- Add detached failure provenance: every `WorkflowFailure` carries one authored instruction location plus one runtime-created root/branch/item occurrence. Provenance attaches when the failure is created, survives ordered aggregation and `orcacore-json-v1` round-trip, and does not introduce nested ancestry coordinates for a capability that remains deferred.
- Separate application, engine/hosting, provider-authoring, runtime-protocol, and implementation tiers. Hide compiled IR, fiber/scope routing identities, commands, checkpoints, provider records, and hosted-loop implementations from normal application contracts. Use only the exact reviewed implementation and owning-test `InternalsVisibleTo` edges needed by the package split; do not keep those types public or replace them with reflection/public bridge helpers merely to cross an assembly boundary.
- Publish the exact ordinary application facade: independently declared immutable definitions and references with restart-stable durable identity; explicit mode-specific application-configuration registration; atomic startup preflight of the staged definition batch; exact-reference handle lookup that never registers; a closed registered/host-incompatible/fingerprint-conflict result with deterministic mode/static-pool/dispatcher/fingerprint validation and cast-free `GetHandleOrThrow()` projection; closed typed start results; typed start/reopen handles; detached snapshot/root-state/output queries; notification-driven output and DAG-terminal waits; cooperative cancellation request; and immediate fenced termination. Pause/resume/retry/archive/purge and instance enumeration/bulk selection/query/statistics remain deferred.
- **BREAKING** Replace `IWorkflowEventClient` and its caller-managed two-route/redelivery contract with durable-only `IWorkflowEventIngress`. One fixed-codec self-routing envelope carries stable event contract name/version, event and correlation identities, occurrence time, payload, and an instance, correlation, definition-fanout, or exact-definition start-or-deliver route. Its closed result is `Accepted`, `Duplicate`, or `Rejected` with exact event-conflict, direct-target, start-conflict, and fanout-limit reasons; only the first two mean the normalized envelope and route intent are durably owned and safe for broker acknowledgement. An event accepted before a matching wait is retained in a route-level or per-instance inbox, races wait registration atomically, and later activates and rehydrates a cold matching instance; `NoActiveWait` is removed. Start-or-deliver carries distinct typed workflow input and event payload under one start-idempotency key, atomically owns a pending start intent and event, and lets a definition-owning host materialize the compatible instance/inbox/continuation; fanout commits a provider-state snapshot of current nonterminal targets and excludes later instances.
- Add explicit payloadless/typed workflow-event contract descriptors as the stable wire identity used by `Wait`, ingress, and durable `Publish`. CLR type names and Temporal-style workflow/signal attributes are not registration or routing truth, and v1 performs no workflow or event assembly scanning; application-owned modules may expose ordinary explicit registration extensions.
- Add durable workflow-authored `Publish` and a complete public outbound envelope containing stable event/causation/correlation identity plus origin instance/definition/version. The workflow transition and outbox record commit atomically. `OrcaCore.Durable.Hosting` exposes an application-shaped `IWorkflowEventDispatcher` with one exact dispatch method and closed success/retryable/permanent result; applications implement it with MassTransit, Rebus, SNS, SQS, RabbitMQ, or another transport, while OrcaCore supplies persistence, claims, retries, poison handling, and at-least-once dispatch but no transport SDK integration.
- Publish only role-specific hosting: mode-specific builders returned by `AddOrcaCoreEphemeralEngine` and `AddOrcaCoreDurableEngine`, callback-only `AddOrcaCoreDurableEventIngress`, development/test `AddOrcaCoreInMemoryDurableProvider`, production `AddOrcaCorePostgreSqlDurableProvider` and `AddOrcaCoreSqlServerDurableProvider`, and `OrcaCore.Dag.Hosting.AddOrcaCoreDag`. PostgreSQL and SQL Server each supply one complete independently certified durable-provider role set; SQL Server is a new current-port implementation rather than a resurrection of the deleted provisional provider. Engine builders accept only their mode's built definitions through explicit `AddWorkflow` calls and freeze the staged batch before progression. Hosting retains split extension owners, programmatic options, mutually exclusive engine roles, and no catch-all `AddOrcaCore`, separate hosted-service toggle, implicit mode, serializer hook, binder claim, or reflection discovery.
- Make `OrcaCore` the primary application contracts/authoring package rather than a dependency-only meta-package. Fix every v1 PackageId/assembly owner/direct edge and validate clean consumers from the repository-local Phase 0 feed.
- Define durable resource governance as one serialized aggregate per configured provider partition, with fixed FIFO request order, atomic multi-pool grants, typed unknown-pool rejection before mutation, positive-only resize, exact grant/cancel and confirmation precedence, immutable creation definitions distinct from replayed current capacity, exact reservation/resize/confirmation accounting, and one expected-version `IDurableResourceGovernanceStore` append contract.
- Define the per-instance execution-path token model: runnable root/branch/item fibers own one token; parking and joins release it; parents release before root fan-out and reacquire for merge; root fixed branches and root-`ForEach` items queue deterministically; timed-out token-ignoring bodies retain only physical throttle/transient capacity.
- Remove implementation-only `MaxActiveFibers` from compiler acceptance, runtime item admission, runtime terminal failure, and structural fingerprinting, including its diagnostics. All fixed root-`Parallel` fibers exist at scope start and queue only for path tokens. Root `ForEach` separately caps admitted nonterminal items at the lower host/node value; parking retains that item slot, so completion is conditional on admitted items not depending on pending ones. No replacement branch-width limit is added without a concrete v1 safety requirement.
- Make `docs/specs/17-public-authoring-contract.cs` together with the selected-mode matrix the exact compile/reflection guard baseline. Add the complete diagnostic/location catalog, codec, detached-attempt-state, public-facade/event-contract/ingress/dispatcher, application-configuration definition catalog, buffered-wait/cold-reactivation, inbox/outbox crash, path-token, runtime-pre-child DAG mapping, resource-governance provider, deterministic four-barrier crash, restart, deadline, structured-join, operation-identity, and lease-protocol guards. Every Phase 0 task 3.1 through 3.12 and an independent approval are required before implementation proceeds.

## Capabilities

### New Capabilities

- `developer-facing-surface`: Defines the v1 application surface, tier/package boundaries, explicit future-capability registry, and supported consumer journeys.

### Modified Capabilities

- `workflow-authoring`: Defines mode-first typed workflows, the reduced node matrix, joins, bounded durable `ForEach`, explicit event-contract waits, durable `Publish`, ephemeral lambdas, deadlines, scoped leasing, and deferred-node absence.
- `workflow-contracts`: Defines all-mode typed workflow references/input/output, event contract descriptors and self-routing envelopes, branch and item outcome contracts, failure provenance, `StepOperationId`, immutable lease requests, and portable step boundaries.
- `state-driven-runtime`: Describes supported nested `If` and linear child execution without implying unreachable nested fan-out scopes.
- `durable-runtime`: Defines durable deadlines, stable step occurrence identity, buffered ingress, cold reactivation, start/fanout routing, durable publish/outbox dispatch, scoped lease ownership/reconciliation, immutable definition binding, and runtime-owned DAG progression.
- `management-and-querying`: Aligns typed asynchronous handles and exposes safe durable lease quarantine/reconciliation operations.
- `saga-orchestration`: Removes saga from the v1 callable surface while retaining an explicit future capability entry.
- `repository-foundation`: Establishes one-way package direction, `OrcaCore.Dag`, and strict separation from Kubernetes/AWS/job-scheduler projects.
- `quality-and-verification`: Replaces rejected guards and adds mechanical proof for the final v1 surface and its deferred absences.
- `event-routing-and-waits`: Replaces non-buffering two-route delivery with durable self-routing acceptance, pre-wait buffering, atomic matching, cold activation, start, and committed-snapshot fanout.
- `durable-persistence-and-outbox`: Defines durable route/per-instance inbox ownership, atomic outbound event writes, transport-neutral dispatcher delivery, retry/poison outcomes, and no-silent-loss rules.

## Impact

- The selected-mode matrix, canonical OpenSpec specs, guide, and semantic appendix already reflect
  the independently approved reshape amendments synchronized by completed task `10.14`. The separate
  `harmonize-downstream-capability-specs` change remains pending its task `1.4` independent approval;
  its deltas SHALL NOT be synchronized into canonical specs before that approval.
- Affected product areas include application contracts and authoring, both engines, the durable driver, definition catalogs, durable ingress/inbox/outbox, hosting, management, the InMemory/PostgreSQL/SQL Server provider set, `OrcaCore.Dag`, broker-adapter samples, tests, package metadata, and canonical specifications.
- Existing names and signatures are provisional. Implementation SHALL delete rejected paths directly and SHALL NOT add compatibility shims, obsolete aliases, or placeholder members.
- The archived structured-fiber implementation remains the execution substrate, but its provisional authoring surface is not accepted merely because source already exists.
- `add-runtime-concurrency-limits` remains coordinated for transient host limits. The host owns `MaxConcurrentExecutionPathsPerInstance`; every fixed root-`Parallel` branch fiber exists and runnable branches receive tokens in authored order, both-mode root `ForEach` uses the lower of host and node-local admitted-item limits, and DAG scheduling uses its separate node limit. No live-fiber admission resource participates in v1 workflow semantics.
- Kubernetes/EKS/AWS scheduling remains a companion integration concern. OrcaCore supplies only generic workflow, identity, wait, deadline, and resource-safety contracts.
